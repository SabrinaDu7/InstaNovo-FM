# Session log: the external-dataset results read together, and why the 40M trained here does not reconstruct fragments like the released one
Date: 02/10/2026

## Initial purpose of the session

Summarise the external-dataset results (`docs/results/eval_*.md`), plan extracting the evaluation suite into a package
another spectrum tokenizer can use, plot every metric, then explain the 40M trained here's fragment-reconstruction gap
to the released 40M and retrain to test one explanation. Both clones (workstation, nibi) on `sdu/reproduce-results-40M`.

## What was accomplished during the session

The purpose shifted from reporting to diagnosis: a 1,196 ppm median y-ion error on UPS1 for the 40M trained here
(252 ppm released) led to the released checkpoint's own training counters.

| Task | What we learned |
| :---- | :---- |
| Results of the four external datasets read together (CAMPI retrieval had landed since the last log) | The released 40M against its LCFM-test reference: MS2Bac at or above it on nearly every row; CAMPI (88.6 % of peptides absent from the corpus) degraded but working, probes hold (instrument 0.943, collision energy 0.909), reconstruction drops (48.1 % vs 55.0 % fragment-group bin accuracy, b-ion median error 1,569 vs 277 ppm); UPS1 (ion-trap CID) weakest (38.4 %, trainer bin accuracy 13.8 % vs 27.4 %). Recall@1 on UPS1 (0.933) and ProteomeTools (0.970) measures the replicate structure (one digest run three times; about 96 spectra per peptide), not the model. Proportional recall@1 is bounded by 1/(group size − 1), so it is not comparable across datasets either; an earlier reading of CAMPI's 0.051 against the corpus's 0.068 as "below the corpus" was wrong. |
| Plan to extract the evaluation suite into a package (not coded) | The seam exists: `embeddings.h5` + `index.faiss` (`eval/embedding_io.py` save/load), `run_tasks_from_embeddings.py`, and the Casanovo/XuanjiNovo extractors. Embedding-only tasks (probes, retrieval, geometry, ESM2, hyperscore, annotation transfer, rescue) move as they are; peak-type classification needs a per-token hook with a token→peak map; IG attribution, attention heads, confidence and trainer validation need the FM's masked-reconstruction head and stay in this package. Two comparability problems to fix on the way: every extractor goes through `FoundationalDataProcessor` (top 200 peaks, intensity floor, sqrt), and theoretical annotation runs only when `store_per_peak_confidence` is on, which is forced off for non-classification models (`embedding_io.py:759, 944`). |
| `scripts/evals/plot_results.py` (commit ce79d46): every metric of the four documents as bar charts, `docs/results/eval_metrics.png` (groups = datasets) and `eval_metrics2.png` (groups = checkpoints, plus the LCFM test reruns in grey and the paper's numbers as diamonds); the PNGs are git-ignored | Reads the rendered tables, and the corpus reruns through `render_results.py`'s getters, so the figures show the documents' numbers. |
| The 1,196 ppm median y-ion error (40M trained here, UPS1) | A median over a two-mode error distribution: a prediction is in the right or the adjacent 0.2 Da bin (hundreds of ppm) or on another peak (whole Da). Above about 45 % bin accuracy the median sits in the first mode, below about 40 % in the second; every spike in the plots is a cell under that threshold (UPS1 y 34.3 % → 1,196 ppm, CAMPI b 37.5 % → 3,259 ppm, LCFM test b 44.6 % → 827 ppm). The IG task saves only summary statistics, so the per-prediction errors that would show the second mode (possibly the neighbouring isotope, 1.003 Da) are not on disk. The underlying gap is real and consistent: the 40M trained here is 3 to 10 points under the released 40M in fragment-group bin accuracy on every dataset, LCFM test included (49.2 % vs 55.0 %). |
| The released 40M checkpoint's metadata (`~/.cache/instanovo-fm/instanovo-fm-mcfm-90k-v0.1.0.ckpt`) | `epoch: 14, global_step: 80001`; its embedded model config is identical to `configs/model/foundation_base.yaml` (125 keys, no difference). Our run's checkpoints are named `model_epoch_07_step_80001.ckpt` / `model_epoch_07_step_90001.ckpt` (11,428 steps per epoch at batch 1,024 over 11.7 M spectra). The released run passed 14 epochs in 80,001 steps, 5,714 steps per epoch: exactly half of ours. Two explanations fit: a global batch of 2,048 (twice the spectra per step), or a training split of about half today's size. The released model is also the step-80,000 checkpoint, not a 90,000-step one. |
| Hugging Face history of `InstaDeepAI/InstaNovo` (95 commits) | The spectra were uploaded once, on 03/09/2026; no earlier revision has `splits/mcfm`, so the hub cannot show an older MCFM. The peptide registry changed between January and April: 4,368,951 peptides (30/01; train 3,495,058) → 5,277,286 (05/03) → 5,613,657 (26/03 onward; train 4,493,959 at release), and 107,699 of the January peptides changed split by the release (none was removed). The corpus grew about 28 % in peptides while the model was in development; the registry counts peptides, not spectra, so it neither confirms nor rules out a half-size training split. If the released 40M was trained on an earlier registry, some of today's validation and test peptides may have been its training peptides (possible, not shown). |
| Correction to `session-2026-09-25-train40M.md` ("the LR scheduler is stepped on every micro-step inside `accelerator.accumulate` … wrong otherwise") | The scheduler is Accelerate's `AcceleratedScheduler` (prepared at `common/trainer.py:175`), whose `step` returns without stepping when `sync_gradients` is False (accelerate 1.14, read from the source). Gradient accumulation advances the schedule once per optimizer update; `grad_accumulation=2` is safe. |

## Problems encountered
- nibi requires MFA: an SSH command from the agent fails until the user opens a control master (`ssh -fN nibi`, with
  `ControlMaster auto` / `ControlPersist yes` in `~/.ssh/config`).
- nibi's clone had one unpushed commit (`464768c`, `outputs/` in `.gitignore`) while the workstation had pushed another
  `.gitignore` change; rebased onto origin (08b7979) without conflict and pushed, both clones level.
- `eval_metrics2.png` caption overflowed the figure width; the collision-energy panel mixes the corpus's R² (−1.5 to
  −2.2) with the external datasets' macro-F1, the probe's substitute metric, so its axis is stretched by design.
