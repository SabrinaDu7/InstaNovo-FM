Started 15/10/2026 on branch `sdu/exploring-arch`. A running file: observations are added as they are measured,
each with the run or log they come from; ideas are marked **measured** (a number from a run), **read** (a fact from
the code) or **expected** (an estimate that a measurement would confirm). Nothing in here is implemented unless the
log at the end says so. Earlier observations were scattered over the session logs named in each row; this file is
now their one home for the speed question.

| S15 | **Muon for the encoder's matrices, AdamW for the rest** (owner's question, 20/10). The trainer builds one `AdamW` over every parameter (`trainer/train.py:setup_optimizer`: lr 1e-4, weight decay 0, `fused=True`; `gradient_clip_val` 1.0 in `configs/foundational.yaml`, the code's fallback of 10 never applies). No gain in this regime. The regime is the caveat: the literature's advantage is at large batch, where AdamW's noisy second moment hurts most, and micro-batch 32 is the opposite corner; the local run-to-run spread is unmeasured. The large-batch question only the cluster can answer (10,000-step smoke at batch 2,048, 2.5 GPU-hours on rrg's 3-hour partition). Cheapest test: the 10,000-step smoke recipe on def-hsn_gpu (2.5 GPU-hours) against the baseline's step-10,001 point (6,342 ppm, bin accuracy 12.03), then a full run if the gap exceeds the run-to-run spread (about 100 ppm, 0.35 points). | `trainer/train.py:setup_optimizer`; a small `optim/muon.py` | if the literature factor holds: 19 h to 10-14 h for the same loss, or a better model at 90,000 steps | read; parameter split measured on the workstation |
